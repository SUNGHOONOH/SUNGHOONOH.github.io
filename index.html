01

지원 동기

문제를 이해한 뒤,
차근차근 확인하는 편입니다.

넛지헬스케어의 캐시워크는 사용자의 작은 행동 변화를 건강 습관으로 연결하는 서비스라고 이해하고 있습니다. 이 과정에서 데이터 분석은 단순히 지표를 계산하는 일을 넘어, 사용자가 어디에서 이탈하는지와 어떤 변화가 실제 서비스의 영향인지 확인해 개선으로 연결하는 역할이라고 생각해 지원했습니다. 특히 공고에서 제시한 KPI, 사용자 행동 로그, Funnel·Cohort·Retention 분석과 A/B 테스트·인과추론을 활용한 결과 해석에 관심이 있습니다.

저는 프로젝트에서 전처리·시각화·모델링을 직접 진행하고, 가설을 세운 뒤 데이터의 품질과 결과를 확인하는 흐름을 만들어 왔습니다. 또한 LLM과 벡터 DB를 연결한 기능을 실제 웹·데스크톱 서비스로 구현하고 배포하며, 분석 결과를 사용자가 이용할 수 있는 형태까지 이어 본 경험이 있습니다. 산업기능요원으로 근무하게 된다면 캐시워크의 데이터 흐름과 지표 정의를 정확히 배우고, 분석 결과를 서비스 개선으로 연결하는 데이터 분석가로 성장하고 싶습니다.

01 · 천안시 119 복귀 경로 최적화

Situation
119 구급차가 병원이나 현장에서 센터로 복귀할 때, 다음 신고 수요를 함께 고려할 수 있는지 분석하는 공모전 프로젝트였습니다.
Task
신고접수·구급활동·센터·병원·도로망 데이터를 연결하고, 시공간 수요와 복귀 경로를 분석할 수 있는 데이터와 도표를 만드는 일을 맡았습니다.
Action
시간과 공간 기준을 맞춰 데이터를 전처리하고, 도농·시간대별 패턴을 시각화했습니다. 이후 수요예측과 병원 후보, 복귀 경로를 시간 순서대로 비교하는 모델링과 시뮬레이션을 진행했습니다.
Result
팀이 제안한 분석 구조와 작동 방식을 발표 자료로 설명할 수 있도록 정리했습니다. 최종 공모전 결과 발표 전이므로 확정 성과 수치는 공개하지 않고, 담당 작업과 분석 구조 중심으로 공개하고 있습니다.

02 · Subnota 검색·AI 서비스 구현

Situation
메모와 저장한 링크가 쌓여도 시간이 지나면 필요한 내용을 다시 찾기 어려웠고, 단순한 키워드 검색만으로는 서로 다른 시점에 기록한 맥락을 연결하기 어려웠습니다. 일정이나 할 일을 메모 안에 적어도 사용자가 직접 다시 옮겨야 하는 부담이 있었습니다.
Task
사용자가 메모를 작성하는 흐름을 방해하지 않으면서 관련 기록과 일정 후보를 다시 발견할 수 있는 애플리케이션을 만들고자 했습니다. 동시에 개인적인 기록을 다루는 서비스인 만큼 빠른 기능 구현보다 로컬 우선 저장과 데이터 보호를 먼저 고려했습니다.
Action
React·Electron과 SQLite를 기반으로 메모를 기기에 먼저 저장하고, 작성 중 관련 맥락을 찾는 검색은 로컬 임베딩으로 처리했습니다. 이후 Supabase 동기화·PostgreSQL/pgvector·FastAPI를 연결해 저장 링크 요약, 메모 속 일정 후보 추출, Topics 기반 관련 기록 연결을 구현했습니다. 모든 요청을 실시간으로 서버에 보내기보다 검색은 즉시, 일정·토픽 보강은 백그라운드 배치로 나누어 사용성과 운영 비용 사이의 균형을 잡았습니다.
Result
메모를 저장하는 데서 끝나지 않고, 사용자의 기록 속 맥락 패턴을 바탕으로 관련 메모·일정·링크를 다시 연결하는 제품 흐름을 완성했습니다. 웹사이트와 macOS·Windows 데스크톱 배포본을 실제로 운영하고 있으며, 서비스는 subnota.com에서 확인할 수 있습니다. 전체 구조와 개발 과정은 GitHub에 정리했습니다.

03 · 제조공장 에너지 데이터 분석

Situation
설비별 전력 계측 데이터가 15분 패널 형태로 제공되었고, 값의 품질과 설비별 운영 패턴을 먼저 확인해야 했습니다.
Task
원자료 집계와 제공 특징량을 비교하고, 데이터 오류와 실제 운영상 점검 후보를 구분한 뒤 공장·설비 단위의 분석 구조를 만드는 일을 진행했습니다.
Action
시간축·중복·gap·물리 범위를 검증하고, IQR과 Isolation Forest를 후보 플래그로 남겼습니다. 이후 1시간 집계, 피크·ramp, 역률·전류 불균형·전압 일탈, 설비별 패턴 특징량과 K-Means/PCA까지 연결했습니다.
Result
고부하와 전력품질 신호가 함께 나타나는 추가 점검 후보를 좁히는 분석 흐름을 만들었습니다. 원본 데이터는 공개하지 않고, 실제 분석 노트북·논리 지도·재실행 가능한 코드만 GitHub에 정리했습니다.
03

강점 및 직무 역량

작업을 끝까지 확인하고
기록하는 편입니다.

문제를 구조화하는 힘

서로 다른 형태로 들어온 텍스트와 계측 데이터를 살펴보고, 분석 가능한 단위와 기준으로 나누어 왔습니다. 천안시 119 프로젝트에서는 시간·공간 기준을 맞추고, 제조업 프로젝트에서는 시간축·중복·결측·물리 범위를 먼저 검증한 뒤 분석을 진행했습니다.

가설과 결과를 확인하는 습관

전처리 결과를 시각화하고 모델·시뮬레이션과 비교하면서 결과가 납득되는지 확인하려고 합니다. 단순한 상관관계나 전후 차이만으로 결론 내리기보다 비교 기준과 외부 요인을 점검하고, A/B 테스트와 인과추론을 통해 변화의 효과를 더 정확히 해석하는 방향으로 역량을 확장하고 있습니다.

분석을 서비스로 연결하는 구현력

Python·Pandas·SQL을 활용한 분석부터 React·Next.js·Flask 기반 화면과 AI 기능 구현까지 경험했습니다. Subnota에서는 LLM·임베딩·벡터 DB(pgvector)를 연결해 검색과 요약 기능을 만들고, 웹·데스크톱 서비스로 배포했습니다. 분석 결과를 리포트에 남기는 데서 끝내지 않고 실제 사용 흐름으로 연결해 본 경험입니다.

04

입사 후 포부

처음에는 업무를 정확히 배우고,
작은 개선부터 맡겠습니다.

입사 후에는 먼저 캐시워크의 이벤트 로그와 지표 정의, 데이터 수집·관리 흐름을 정확히 배우겠습니다. 사용자가 어떤 단계에서 이탈하는지 Funnel·Cohort·Retention 관점에서 확인하고, KPI 변화의 원인을 데이터 소스별로 교차 검증하는 기본부터 꼼꼼하게 맡고 싶습니다.

업무에 익숙해진 뒤에는 가설과 핵심 지표를 정리해 실험을 설계하고, A/B 테스트와 인과추론 관점에서 서비스 변화의 효과를 해석해 보고 싶습니다. Python·SQL 기반 분석을 대시보드와 재현 가능한 코드로 남기고, 기획·개발·운영팀과 함께 분석 결과가 실제 사용자 경험 개선으로 이어지도록 꾸준히 배우고 기여하겠습니다.
