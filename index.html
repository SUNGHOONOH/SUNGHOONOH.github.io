01 · 천안시 119 복귀 경로 최적화

Situation
119 구급차가 병원이나 현장에서 센터로 복귀할 때, 다음 신고 수요를 함께 고려할 수 있는지 분석하는 공모전 프로젝트였습니다.
Task
신고접수·구급활동·센터·병원·도로망 데이터를 연결하고, 시공간 수요와 복귀 경로를 분석할 수 있는 데이터와 도표를 만드는 일을 맡았습니다.
Action
시간과 공간 기준을 맞춰 데이터를 전처리하고, 도농·시간대별 패턴을 시각화했습니다. 일부 홀드아웃 지표가 앞선 격자 모델 대신 관측 격자 밖 도로 지점에도 수요를 조회할 수 있는 연속 수요표면을 선택했습니다. 미이송 후 빈 차 복귀 사례를 평가에 포함하고, 과거 자료로 정책을 선택한 뒤 미래 기간에만 직행 복귀와 제안 경로를 같은 신고 흐름에 적용하는 20회 Monte Carlo 시뮬레이션을 진행했습니다.
Result
시간외 평가에서 경로 변경의 영향을 받은 신고의 예상 현장도착시간이 건당 평균 43.3초 순단축되는 결과를 확인했습니다. 이는 현장 운영 실측 성과가 아닌 시뮬레이션 결과이며, 최종 공모전 수상 결과와는 구분해 공개하고 있습니다.

02 · Subnota 검색·AI 서비스 구현

Situation
메모와 저장한 링크가 쌓여도 시간이 지나면 필요한 내용을 다시 찾기 어려웠고, 단순한 키워드 검색만으로는 서로 다른 시점에 기록한 맥락을 연결하기 어려웠습니다. 일정이나 할 일을 메모 안에 적어도 사용자가 직접 다시 옮겨야 하는 부담이 있었습니다.
Task
사용자가 메모를 작성하는 흐름을 방해하지 않으면서 관련 기록과 일정 후보를 다시 발견할 수 있는 애플리케이션을 만들고자 했습니다. 동시에 개인적인 기록을 다루는 서비스인 만큼 빠른 기능 구현보다 로컬 우선 저장과 데이터 보호를 먼저 고려했습니다.
Action
React·Electron과 SQLite를 기반으로 메모를 기기에 먼저 저장하고, 작성 중 관련 맥락을 찾는 검색은 로컬 임베딩으로 처리했습니다. 이후 Supabase 동기화·PostgreSQL/pgvector·FastAPI를 연결해 저장 링크 요약, 메모 속 일정 후보 추출, Topics 기반 관련 기록 연결을 구현했습니다. 입력이 멈춘 뒤에만 추천하도록 작성 단계를 구분하고, 본인과 지인 2명의 실사용 이벤트 로그를 확인해 초기 5초 대기값을 4초로 조정했습니다. 이전 요청 결과가 현재 추천을 덮지 않도록 최신 문맥의 결과만 반영했습니다.
Result
메모를 저장하는 데서 끝나지 않고, 사용자의 기록 속 맥락 패턴을 바탕으로 관련 메모·일정·링크를 다시 연결하는 제품 흐름을 완성했습니다. 실사용 로그를 근거로 노출 조건을 조정했지만, 사용자 규모가 작아 통계적 검증 단계는 아니며 추천 수락률·재방문율·A/B 테스트 성과로 확대해 주장하지 않았습니다. 웹사이트와 macOS·Windows 데스크톱 배포본은 subnota.com에서 확인할 수 있습니다.

03 · 제조공장 에너지 데이터 분석

Situation
설비별 전력 데이터가 5초 원자료와 15분 특징량 형태로 제공되었고, 공장 전체 평균만으로는 설비별 운영 패턴과 점검 후보를 구분하기 어려웠습니다.
Task
두 데이터의 정합성을 비교하고 결측·중복·시간 공백·물리적 오류를 먼저 확인한 뒤, 고부하와 전력품질 신호를 비효율의 확정값이 아닌 추가 점검 후보로 정의하는 분석 구조를 만드는 일을 진행했습니다.
Action
5초 원자료 집계와 제공 특징량을 대조하고, IQR과 Isolation Forest는 이상치를 삭제하지 않고 후보 플래그로 남겼습니다. 피크 기여율·부하율 등 설비 단위 지표를 설계한 뒤 지표의 구분력과 값의 신뢰성을 나눠 검토했습니다. 공장 전체 평균에서 설비 단위 분석으로 방향을 바꾸고, 15분·1시간 패턴, 피크·ramp, 역률·무효전력·불균형·전압 일탈, 설비별 특징량과 K-Means/PCA를 연결했습니다.
Result
여러 설비의 동시 고부하와 전력품질 신호를 바탕으로 점검 우선 설비 2대를 좁혔습니다. 운전 상태별 회귀에서 부하 변동성이 고부하 상태 약 20%, 저부하 상태 약 20~26% 높게 나타나는 연관성을 근거로 운영 개선안을 제안했습니다. 관측된 연관성을 실제 에너지 절감률이나 인과효과로 과장하지 않고, 생산량·정비 기록이 추가되면 회귀·인과추론으로 확장할 수 있도록 한계를 함께 정리했습니다.

04 · ITDA 소비기한 OCR 파이프라인

Situation
상품 사진에는 소비기한 외에도 제조일·로트번호·바코드 숫자가 섞여 있어, 사진 전체를 OCR로 읽는 것만으로는 필요한 날짜를 안정적으로 고르기 어려웠습니다.
Task
소비기한 표시 영역 검출·문자 인식·날짜 역할 판단을 분리하고, GPU가 없는 4코어 CPU 채점 환경에서도 재현 가능한 추출 파이프라인을 만드는 일을 맡았습니다.
Action
직접 촬영한 상품 사진을 수집·라벨링하고, 같은 상품의 연속 촬영분이 학습과 검증에 섞이지 않도록 분리했습니다. 빛 번짐 보정만으로 개선되지 않자 오답을 숫자 인식·영역 검출·날짜 선택 오류로 나눴고, 두 단계 검출은 정확도와 속도 비교 결과를 근거로 채택하지 않았습니다. 기본 경로와 실패·저신뢰 사진에만 쓰는 보정 경로를 분리해 제출 환경까지 점검했습니다.
Result
고정 검증 사진 200장에서 날짜 완전일치율 93.5%(187/200)를 확인했습니다. 별도 실사 사진에서는 성능 저하를 발견해 글줄 정렬과 방향 보정을 추가 과제로 남겼으며, 해당 수치는 팀 내부 검증 결과이지 대회 비공개 채점 성적은 아닙니다.
