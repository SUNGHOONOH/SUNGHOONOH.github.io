01

지원 동기

문제를 이해한 뒤,
차근차근 확인하는 편입니다.

한시큐리티가 정보보안 컨설팅과 소프트웨어 개발을 통해 고객의 정보와 자산을 보호하는 회사라는 점에 관심이 생겨 지원했습니다. 보안 업무도 결국 정확한 자료를 바탕으로 문제를 확인하고, 필요한 내용을 다른 사람이 이해할 수 있도록 전달하는 과정이 중요하다고 생각합니다.

저는 프로젝트에서 전처리·시각화·모델링을 직접 해보고, 그 결과를 AI 서비스와 화면으로 연결해 왔습니다. 산업기능요원으로 근무하게 된다면 먼저 회사의 업무와 데이터 흐름을 정확히 배우고, 제가 할 수 있는 부분부터 꾸준히 맡아 팀에 도움이 되고 싶습니다.

01 · 천안시 119 복귀 경로 최적화

Situation
119 구급차가 병원이나 현장에서 센터로 복귀할 때, 다음 신고 수요를 함께 고려할 수 있는지 분석하는 공모전 프로젝트였습니다.
Task
신고접수·구급활동·센터·병원·도로망 데이터를 연결하고, 시공간 수요와 복귀 경로를 분석할 수 있는 데이터와 도표를 만드는 일을 맡았습니다.
Action
시간과 공간 기준을 맞춰 데이터를 전처리하고, 도농·시간대별 패턴을 시각화했습니다. 이후 수요예측과 병원 후보, 복귀 경로를 시간 순서대로 비교하는 모델링과 시뮬레이션을 진행했습니다.
Result
팀이 제안한 분석 구조와 작동 방식을 발표 자료로 설명할 수 있도록 정리했습니다. 최종 공모전 결과 발표 전이므로 확정 성과 수치는 공개하지 않고, 담당 작업과 분석 구조 중심으로 공개하고 있습니다.

02 · Subnota 검색·AI 서비스 구현

Situation
메모와 저장한 링크가 쌓여도 시간이 지나면 필요한 내용을 다시 찾기 어려웠고, 단순한 키워드 검색만으로는 기록의 맥락을 연결하기 어려웠습니다.
Task
로컬에 먼저 안전하게 저장하면서도 LLM과 벡터 검색을 활용해 관련 기록을 찾고, 실제로 사용할 수 있는 웹·데스크톱 서비스로 연결하는 것을 목표로 했습니다.
Action
React·Electron과 SQLite를 기반으로 local-first 흐름을 만들고, Hugging Face 임베딩과 Supabase PostgreSQL/pgvector 검색을 FastAPI 백엔드에 연결했습니다. 요약·일정 추출·관련 메모 검색 기능을 웹과 앱 구조에 맞춰 나누고, 공개 웹사이트와 배포 가능한 운영 구조까지 구성했습니다.
Result
메모를 작성하고 저장하는 데서 끝나지 않고, 임베딩 검색과 LLM 기능이 실제 제품 흐름 안에서 동작하도록 구현했습니다. 웹사이트는 subnota.com에서 확인할 수 있고, 전체 구조와 코드는 GitHub에 정리했습니다.

03 · 제조공장 에너지 데이터 분석

Situation
설비별 전력 계측 데이터가 15분 패널 형태로 제공되었고, 값의 품질과 설비별 운영 패턴을 먼저 확인해야 했습니다.
Task
원자료 집계와 제공 특징량을 비교하고, 데이터 오류와 실제 운영상 점검 후보를 구분한 뒤 공장·설비 단위의 분석 구조를 만드는 일을 진행했습니다.
Action
시간축·중복·gap·물리 범위를 검증하고, IQR과 Isolation Forest를 후보 플래그로 남겼습니다. 이후 1시간 집계, 피크·ramp, 역률·전류 불균형·전압 일탈, 설비별 패턴 특징량과 K-Means/PCA까지 연결했습니다.
Result
고부하와 전력품질 신호가 함께 나타나는 추가 점검 후보를 좁히는 분석 흐름을 만들었습니다. 원본 데이터는 공개하지 않고, 실제 분석 노트북·논리 지도·재실행 가능한 코드만 GitHub에 정리했습니다.
